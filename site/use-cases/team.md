# One developer, a team of agents

A project with one maintainer still has the rituals: a daily, a refinement, a plan, a review, a QA
round, a release. What it lacks is people to do them.

**The setup, once.** The team editor starts from a template and brings the agents a project like
this needs: a Product Owner that reads the tracker, a Tech Lead that reads the code host and runs
commands, a Developer and a QA that work in a sandbox, a Reviewer that reads the branch. The five
system agents — the ones behind the ceremonies — are already there. Later a squad can be given a
scope, so the runs that belong to it are decided by the labels, the folders or the repositories they
touch.

**The daily.** The ceremony runs by voice on the way to work or by text at the desk. Each agent
reads before it speaks, so the stand-up is a prepared one: what moved, what is stuck, what it wants
from you.

**The work.** The issues a label points at start runs on their own. An agent that cannot decide
opens a question and waits, and the question goes to whoever the agent turns to before it reaches
you. Where the process asks for a decision, the run stops at a gate.

**What stays with you.** Every write to the code host, and every gate. An autonomous agent writes
its comment by itself and says so; the branch push and the pull request always wait.

The agents, the roles and the permissions are in
[Development cycles](/reference/cycles) and [The runner](/reference/runner).
