## Português

A interface do Coxia existe em português (Brasil) e em inglês (EUA). O idioma vem de `language` na configuração do workspace (`pt-BR` ou `en`); o assistente de configuração e Configurações → Idioma o trocam, e a tela muda na hora. Num navegador (PWA) que ainda não entrou, a tela de pareamento segue `navigator.language` até haver um idioma guardado.

### Onde ficam os textos

| Catálogo (`src/shared/i18n/`) | O que tem |
|---|---|
| `pt-BR.json` / `en.json` | chaves gerais (`updates.*`, `voice.*`, `help.*`, `cycle.*`, `prompt.*`...) |
| `wizard.pt-BR.json` / `wizard.en.json` | o assistente de configuração (`wizard.*`) |
| `ui-<área>.pt-BR.json` / `ui-<área>.en.json` | as telas do renderer, uma chave por texto, `ui.<tela>.<nome>`; áreas `today`, `call`, `settings`, `docs`, `gate`, `shell` (registradas em `ui.ts`) |

Os arquivos são planos, ordenados, com as mesmas chaves nos dois idiomas e os mesmos `{marcadores}` em cada par. Chave que falta no idioma ativo cai no pt-BR e depois na própria chave.

### Como escrever um texto novo

- Componente: `const t = useT();` (ou `useTv()` para o que muda com a voz) e `t('ui.tela.nome', { n })`. Nunca traduza no escopo do módulo: tabelas guardam chaves, o texto sai na hora de renderizar.
- Frase com elemento dentro (`<kbd>`, `<code>`, botão): `tNodes('ui.tela.dica', { key: <kbd>F1</kbd> })`, com `{key}` no texto.
- Plural: duas chaves, `nome_one` e `nome_other`, com `{count}`; quando o texto precisa do número em si, passe `count`.
- Voz: o que fala de "ligação" usa `tv()`; a variante sem voz é a mesma chave com `.novoice` ("conversa" em pt-BR, "chat" em inglês).
- Datas, horas e números: `intlLocale()` no lugar de `'pt-BR'` fixo (`toLocaleDateString(intlLocale(), …)`).
- A chave aparece no código como literal inteiro (`'ui.tela.nome'`), sem montar com `${}`: assim o teste acha chave inexistente e chave sem uso. Para uma família (estado → texto), escreva um mapa de literais.

### Conferência

`npm run i18n:lint` lê o renderer com o parser do Babel e falha (código 1) se sobrar texto de tela fora de `t()`: texto JSX, `title`/`aria-label`/`placeholder`/`alt`/`label`, literais e templates que parecem frase e locale fixo em `toLocale*String`/`Intl`. Também confere a paridade de chaves entre os pares de catálogo. Texto que é máquina e não pessoa (seletor CSS, valor de estilo, comando de shell, nome de produto, assertiva do programador) leva `// i18n-ignore` na linha, ou `// i18n-ignore-next-line` na de cima. `--scope main` mostra o mesmo para o processo principal; `--file <caminho>`, `--json`, `--dir <pasta>` e `--max N` ajudam a trabalhar. O CI roda o comando e bloqueia.

`test/ui-i18n.test.ts` cobre a paridade, os marcadores, as chaves usadas e as sem uso, a troca de idioma e o próprio lint.

### O que ainda vem do processo principal

Textos que o processo principal monta e a tela só mostra (saúde, retro, radar, acesso pelo navegador, notas do assistente) seguem o idioma do catálogo `main.*`, que é de outro trabalho. O que o agente escreve (turnos, ata, decisões) segue o idioma dos prompts e é dado gravado: não é traduzido depois.

## English

Coxia's interface comes in Portuguese (Brazil) and English (US). The language is `language` in the workspace configuration (`pt-BR` or `en`); the setup wizard and Settings → Language change it, and the screen follows at once. In a browser (PWA) that has not signed in yet, the pairing screen follows `navigator.language` until a language is stored.

### Where the strings live

| Catalog (`src/shared/i18n/`) | What it holds |
|---|---|
| `pt-BR.json` / `en.json` | general keys (`updates.*`, `voice.*`, `help.*`, `cycle.*`, `prompt.*`...) |
| `wizard.pt-BR.json` / `wizard.en.json` | the setup wizard (`wizard.*`) |
| `ui-<area>.pt-BR.json` / `ui-<area>.en.json` | the renderer screens, one key per string, `ui.<screen>.<name>`; areas `today`, `call`, `settings`, `docs`, `gate`, `shell` (registered in `ui.ts`) |

Files are flat and sorted, with the same keys in both languages and the same `{placeholders}` in each pair. A key missing in the active language falls back to pt-BR, then to the key itself.

### Writing a new string

- Component: `const t = useT();` (or `useTv()` for what changes with voice) and `t('ui.screen.name', { n })`. Never translate at module scope: tables hold keys, the text is produced at render time.
- A sentence with an element inside (`<kbd>`, `<code>`, a button): `tNodes('ui.screen.hint', { key: <kbd>F1</kbd> })`, with `{key}` in the text.
- Plurals: two keys, `name_one` and `name_other`, with `{count}`; pass `count` when the text needs the number itself.
- Voice: anything that says "call" uses `tv()`; the voice-off variant is the same key plus `.novoice` ("conversa" in pt-BR, "chat" in English).
- Dates, times and numbers: `intlLocale()` instead of a hard-coded `'pt-BR'` (`toLocaleDateString(intlLocale(), …)`).
- A key appears in the code as a whole literal (`'ui.screen.name'`), never built with `${}`, so the test can find missing and unused keys. For a family (state → text), write a map of literals.

### Checking

`npm run i18n:lint` reads the renderer with the Babel parser and fails (exit code 1) if any screen text is left outside `t()`: JSX text, `title`/`aria-label`/`placeholder`/`alt`/`label`, literals and templates that look like prose, and a hard-coded locale in `toLocale*String`/`Intl`. It also checks key parity between catalog pairs. Text meant for the machine and not for a person (a CSS selector, a style value, a shell command, a product name, a programmer's assertion) takes `// i18n-ignore` on the line, or `// i18n-ignore-next-line` on the line above. `--scope main` shows the same for the main process; `--file <path>`, `--json`, `--dir <folder>` and `--max N` help while working. CI runs it and blocks on a failure.

`test/ui-i18n.test.ts` covers parity, placeholders, used and unused keys, the language switch and the lint itself.

### Glossary (pt-BR ↔ English)

See the table in the Portuguese section above: the terms are the same. Each ceremony's name comes from the workspace's cycle template (`cycle.label.*`), so "pré-daily" is "pre-daily" and only becomes "pre-standup" if the template says so.

Commands typed into a ceremony chat accept both languages ("próximo" and "next", "aprofundar" and "deepen"...).

### What still comes from the main process

Text the main process builds and the screen only shows (health, retro, radar, browser access status, wizard scan notes) follows the `main.*` catalog, which belongs to other work. What an agent writes (turns, minutes, decisions) follows the prompts' language and is stored data: it is not translated afterwards.
