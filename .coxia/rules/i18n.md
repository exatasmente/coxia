# Internationalization

The interface, and the text sent to the agents, exist in **Brazilian Portuguese (`pt-BR`)**
and **English (`en`)**. Portuguese is the source language: it is where a missing key falls
back to. Adding a third language is one more catalog and a few lines in
`src/shared/i18n/index.ts`.

## The rules

1. **Every user-facing string goes through `t()`.** No literal text in JSX, in a `title` or
   `aria-label` attribute, in a notification or in an error shown to a person. In the renderer
   use the hook (`const t = useT()` from `src/renderer/src/i18n.ts`) so the screen re-renders
   when the language changes; in the main process and in `src/shared/` import `t` from
   `src/shared/i18n`.
2. **Both catalogs, always.** A key is defined in `src/shared/i18n/pt-BR.json` **and**
   `src/shared/i18n/en.json`. The setup wizard has its own pair, `wizard.pt-BR.json` and
   `wizard.en.json`, merged into the same catalogs.
3. **The same placeholders in both.** Never write "GitLab", "MR" or "pre-daily" in a text
   shown for any workspace: use the placeholder (`{vcsName}`, `{cr}`, `{ceremony}`, ...). A key
   that needs another sentence on one host has a `.on-<kind>` variant; one only true of the SDD
   template with its default parameters has the plain wording of that template and a variant
   for the cycle that differs (`.off-sdd`, `.own-ceremony`, `.own-target`, `.own-retro`). The
   variants in force are `Terms.flags` (`cycleVariants()` in `src/shared/cycles/terms.ts`); the
   host's wins over the cycle's.
4. **Flat dotted keys** named by area: `settings.title`, `wizard.models.testOk`,
   `prompt.sdd.turn.main`.
5. **Plurals** use the `count` param: `t('history.count', { count: n })` looks for
   `history.count_one` when `n` is 1 and `history.count_other` otherwise.
6. **Compose sentences with placeholders**, not by concatenating translated pieces; word order
   differs between languages.
7. **Texts for the agents are catalog entries too** (`prompt.<family>.<id>`); see
   `rules/development-cycles.md` for the families, the overrides and the placeholders.

A key missing in the active language falls back to `pt-BR`; a key missing everywhere returns
the key itself, so a gap shows up on screen as a raw key and in the lint, never as a crash.

## Voice on, voice off: `tv()`

With voice on the app says "call"; with voice off it says "chat" (English) or "conversa"
(Portuguese). That is a second key, not a string replace: `tv('call.enter')` reads
`call.enter` while voice is on and `call.enter.novoice` while it is off, falling back to the
plain key when there is no variant. Use `tv()` (or `useTv()` in a component) for any string
that says "call". Both languages need the `.novoice` variant, it must keep the same
placeholders, and it must never say "call". See `rules/voice.md`.

## Catalog tests

`test/i18n.test.ts` and `test/voice-terminology.test.ts` check the catalogs: the suite fails
when a key exists in only one language or when the placeholders differ (a different case or
count of the same name is fine). `test/host-terms-leak.test.ts` renders every key and prompt
for GitHub and Bitbucket and fails on a GitLab word.
`test/gitlab-catalogs-unchanged.test.ts` renders every key of the `main` area for a GitLab
workspace on the SDD template against a snapshot, and fails on any difference outside its
short list of intended ones.

## Checking your work

```bash
npm run i18n:lint                          # both catalogs define the same keys, renderer literals at 0
node scripts/i18n-lint.mjs                 # a table of the files with the most literal strings
node scripts/i18n-lint.mjs --file <path>   # every finding of one file
node scripts/i18n-lint.mjs --max <n>       # exit 1 when the total is above n (a ratchet)
```

The literal lint is a heuristic (JSX text, `title`/`aria-label`/`placeholder`/`alt`/`label`
attributes and string literals that look like prose); it reports, and a ratchet keeps the
number from growing. `npm run i18n:lint` is what CI enforces. Every string that talks about a
"call" also needs its `.novoice` variant.
